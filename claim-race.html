Claim Race

Bitmap claims waiting to be mined, watched live. For each one: is its number already taken, and is another claim for the same number waiting with a higher fee? Only the first claim of a number is a bitmap; a later one is a copy.

Read first: claims appear as soon as mempool.space reports them, so you see them fast. Each one says "checking…" until a second site (ordpool.space) agrees, and only then gets its tick. Some claims may not be confirmed yet, and some may not be mined at all. This page only shows what we can see right now.

The last 50 blocks: what claims paid

Reads the last 50 blocks from their own bytes: every claim of a number in that window, the fee it paid (from mempool.space's fee list for each block), which one won, and who each claim went to. About 75 MB to download, so it starts when you ask.

How it works, and what it can't see

  • The live feed is mempool.space's: new waiting transactions arrive in batches about every 10 seconds, each with its bytes. Each claim is read from its own bytes by the Block Manifest's reader (the halls' rules: the body exactly "N.bitmap", no delegate, no compression).
  • Each claim is also looked up on a second site (ordpool.space, its own node) to show it is really waiting there too. A new transaction can take a little while to reach it, so it is asked up to 3 times before "not found"; a site that doesn't answer is shown as that, not as "not found".
  • A transaction can hold more than one claim: every one is read. Answers of "not taken yet" are asked again at each new block, in case a claim this page never saw took the number; claims still waiting are looked up again too, in case one was mined before its bytes were read.
  • Taken or not: below block 942,000, bop's on-chain index (checked with ord); from 942,000, the portal's Bitmap Record, and for the newest blocks the blocks themselves.
  • Fee: what the claim pays per vbyte, counting any child transaction paying for it. Higher usually wins, but a miner decides: nothing here is certain until it is mined.
  • It can't see transactions sent straight to a miner, the first seconds before mempool.space hears of one, and when the page opens it reads only the next 8 blocks' worth of waiting transactions (mempool.space's projected blocks): a claim waiting further back is seen only if it moves up.
